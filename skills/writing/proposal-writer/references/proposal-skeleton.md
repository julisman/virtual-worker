# Proposal skeleton

The canonical section order. Every section appears in every proposal unless the user
explicitly cuts it. Per section: what it must contain, and the open questions to ask
the user when the input doesn't answer them.

## 1. Title & header
Contains: proposal title, prepared-for (client + contact), prepared-by, date, version,
offer validity date.
Ask if missing: client contact name/title; how long the offer stays valid (default:
30 days — state it).

## 2. Executive summary (write it last)
Contains: 3–5 sentences — the problem, the proposed solution, headline
timeline + price, the ask. A reader who stops here should still get the deal shape.

## 3. Problem / background
Contains: the client's situation in their own vocabulary; what it costs them
(money, time, risk) to leave unsolved; why now.
Ask if missing: what triggered this request; how they handle it today; success criteria.

## 4. Proposed solution
Contains: what will exist when the work is done; approach in plain language; each
element mapped to a problem element; what makes this approach/vendor the right fit.
Ask if missing: any constraints on approach (tech stack, compliance, existing vendors).

## 5. Scope
Contains two mandatory lists:
- **In scope** — concrete deliverables, quantities where they matter ("up to 5 pages").
- **Out of scope** — adjacent work explicitly excluded (maintenance, content
  migration, training, third-party fees…).
Ask if missing: where the boundaries are; what the client might assume is included.

## 6. Timeline
Contains: phases with durations and the deliverable that ends each; dependencies on
client input flagged per phase; calendar dates only if a start date is known.
Ask if missing: desired start; hard deadlines; client-side review turnaround.

## 7. Pricing / effort
Contains: the model (fixed / T&M / retainer), amounts per line item, currency, tax
treatment, payment schedule, what triggers extra cost.
Ask if missing: ALL of it — pricing is never invented. Also: budget range, payment
terms (default net-30 — state it), currency.

## 8. Risks & assumptions
Contains: 3–6 real risks with mitigations; assumptions the price/timeline rests on
(client provides X by Y, one revision round included…). Include client-side risks.

## 9. Next steps
Contains: how to accept (sign, PO, email confirmation), who does what next, the first
concrete action after acceptance, offer validity restated.

## 10. Appendix (optional)
Contains: team bios, relevant case studies/references, detailed technical specs,
terms & conditions. Only material the user actually supplied.

## Formatting defaults

- Length: 2–4 pages equivalent; executive summary ≤ half a page.
- Tables for pricing and timeline; prose elsewhere.
- One `[TBD: …]` marker style for every unknown, and a consolidated TBD list on top
  of the draft.
